# 数据、任务与规则

## 一行数据代表什么

每一行是某个匿名资产在某个匿名时间点的状态：

```text
row_id | time_id | asset_id | feature_000 ... feature_322
       | responder_0 ... responder_46 | target | weight
```

- `time_id`：全局有序的匿名时间索引；
- `asset_id`：15 个匿名资产之一；
- `feature_000..322`：主办方匿名化后的 323 个可见输入，业务含义不可恢复；
- `responder_*`：训练期可见的辅助标签，可用于多任务或 teacher 研究，测试期不可见；
- `target`：需要预测的未来风险调整表现，仅训练期可见；
- `weight`：该行在评价指标中的重要性，训练期可见，测试评分权重不可直接使用；
- `row_id`：提交对齐键，不是模型特征。

同一个 `time_id` 通常包含 15 个资产，因此数据同时具有两种结构：

1. **纵向结构**：同一资产在连续时间上的历史；
2. **横截面结构**：同一时间不同资产之间的相对位置。

## 评价指标

比赛使用加权零均值 R²：

```text
score = 1 - sum(weight * (target - prediction)^2)
            / sum(weight * target^2)
```

它与普通 R² 的关键区别是分母围绕零计算，而不是围绕目标均值计算。因此：

- 全零预测得分为 0；
- 输出尺度会直接影响得分；
- 高权重且目标绝对值大的行影响更大；
- 对预测均值、time-level 和横截面幅度的校准具有实际意义。

仓库实现见 [`src/quant_competition/metrics.py`](../src/quant_competition/metrics.py)。

## 时序限制

训练、公开测试和最终评测数据按匿名时间顺序排列。预测当前时间时，可以使用：

- 当前批次已经给出的特征；
- 同一资产更早时间的特征；
- 当前 `time_id` 内其他资产的特征；
- 训练阶段学到并冻结的参数。

不能使用：

- 当前时点之后的特征或分布；
- 测试期真实 `target`、`responder` 或评分 `weight`；
- 由未来测试数据反推当前预测的归一化、聚类或门控；
- 外部市场信息与匿名资产做未经许可的映射。

最终评测通过顺序 Time-Series API 调用模型，每次只传入当前 `time_id`，运行环境为 4 CPU、12 GB RAM、无 GPU、无网络。任何 rolling 状态都必须在模型内部按时间更新。

## Fold 与 walk-forward

`fold` 不是随机交叉验证，而是按时间截断的模拟未来：

```text
Fold 6: 过去分区训练 -> 第 6 分区验证
Fold 7: 更长过去训练 -> 第 7 分区验证
Fold 8: Fold 6/7 完成选择后，作为 held-out 未来验证
```

最终 stack 采用：

- 仅 Fold 6 的 OOF 成员拟合权重，评估 Fold 7；
- Fold 6+7 拟合权重，评估 Fold 8；
- Fold 6+7+8 拟合生产权重，生成公开测试预测。

这套设计避免随机切分把未来信息泄漏到过去，但无法完全消除真实市场 regime 变化。这也解释了本项目公开时段与最终隐藏时段之间的差异。
